| 项 | 内容 |
|---|---|

**根因（已隔离验证，非推测）**：

1. `tests/test_save.gd:28` 调用 `_test_city_and_menu_scene()` 时**漏写 `await`**：

   该函数（`test_save.gd:289`）内部第 293 行就有 `await _st.process_frame`，缺 `await` 导致它在第一个
   `await` 处让出、**永不返回**，其后所有语句（含第 300 行 `city.queue_free()`）全部不执行。

2. 因此 `MainCity` 实例**永久留在 `root` 下**，5 个 `hub_entry` 按钮滞留在全局 group 里。

3. `test_campaign.gd:253` 的 `_find_hub_button(city, "战役")` 用 `_st.get_nodes_in_group("hub_entry")`
   **全局查找**（`city` 形参完全没用），命中残留的旧主城按钮，点它 → 挂在已释放场景上的回调不产生
   `stage_select` 面板 → `sel == null` → 断言行失败 → 271 行 `sel._rebuild()` 对 `Nil` 报错。

**隔离验证证据**：

### 冒烟中的两个观察（不构成失败，但要记录）

**观察 A：`wave N 结束(cleared=false) 敌余=0`（W1~W7 全部出现）**

- 归因：**非缺陷，W1~W7 是被冒烟脚本快进的**。`tests/smoke_runner.gd:115` 对 `wave < 8` 调
  `di._force_end_wave()`，而 `wave_director.gd:642` 里 `_force_end_wave()` 固定传 `_finish_wave(false)`。
- `敌余=0` 是因为 `retreat()` 先于 `_finish_wave()` 执行，敌人已被移出 `enemies` group。
- 即 `cleared=false` 只是“强制结束”的标记，**不是“该清完却没清完”**。玩家正常流程走的是
  `_alive_enemies() == 0 → _finish_wave(true)`（`wave_director.gd:218`），冒烟里 W8 就是 `cleared=true`。
- 不算问题，但日志读起来有歧义。建议木匠把 `_force_end_wave()` 的日志改成独立的 `forced` 结果标签，
  别复用 `cleared=false`（`time_up` 也用它，两者混在一起分不清）。

**观察 B：W8 后半段帧率从 ~145 塌到 3~6 fps**

- 证据：`[HB] t=417.7 fps=58` → `t=433.1 fps=6` → `t=539.8 fps=3`，同时 `enemies` 从 129 线性涨到 217。
- 机制：W8 是 Boss 波，`wave_director.gd:219` 在 Boss 存活期间每 10s 调 `_tick_reinforce()` 加 4 个黄巾卒且
  **无上限**（`data/waves.json:116` `reinforcement.count=4, interval=10.0`）；Boss 不死就无限累积。
- 这是**设计口径**（“杀华雄才结束”），不是崩溃，也不是内存泄漏；217 个敌兵 × 每敌 7 节点 ≈ 1500 节点拖垮 headless 渲染。
- 归因：**可接受数值/设计行为**，但需要 @秤砣 确认 W8 真打时长是否合理——本次华雄 **397 秒**才被击杀
  （普通玩家手感上是一次很长、后期卡成幻灯片的战斗）。如果目标时长是 60~90s，那这条要算**数值问题**。
- 附带确认：**无敌兵数量上限**。若玩家一直打不死 Boss，敌兵会无限增长到出问题。建议 @木匠 加个
  `MAX_ENEMIES` 上限（比如 120），或 @秤砣 调整增援间隔。
