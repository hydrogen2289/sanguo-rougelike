## 3. 存档结构设计(★新增)

### 3.1 落盘形式与时机

- **SaveState(autoload)**:跨局持久状态唯一入口;`user://save_v1.json`(Godot user:// 目录,Windows 即 `%APPDATA%\Godot\app_userdata\桃源乱武\`)。
- **写盘时机**(全部走 `SaveState.flush()`,其余时刻只改内存):结算入库(reward_settle)、招募/合成、升级/升星、评星与宝箱变更、退回主菜单、退出游戏。
- **原子写**:先写 `save_v1.json.tmp` 再 `rename` 覆盖;写前将旧文件复制为 `save_v1.json.bak`(单级回滚);加载时 JSON 解析失败 → 自动尝试 .bak → 再失败按新档处理并横幅告警。
- **版本迁移**:根字段 `"version"`;`SaveState.migrate(data)` 按 version 逐级升级(当前只有 v1,迁移骨架先建)。
- **不存局内态**:局内 build(遗物/强化/军资/临时武将)只存在于 RunState,不入存档(§8.4 口径)。

### 4.3 关卡数据表结构(章节/关卡/波次脚本)

契约要点(与 waves.json 同源,`DataDB._validate_waves()` 逻辑复用):

- 塔 1~8 层直接引用现有 `waves.json`(不改字段,由 tower.json 的 `floors_ref: "waves.json"` 指明),满足约束 6。

## 5. 武将养成数值曲线框架(★新增,全部占位)

### 5.1 等级曲线

- 等级域 `L ∈ [1, 30]`;出场基础值:HP(L) = 表值 HP × (1 + 0.08×(L−1));ATK(L) = 表值 ATK × (1 + 0.08×(L−1))。线性 +8%/级为占位起点,验收实测后可在 `economy.json` 加 `level_growth` 字段调。
- 升级耗军资 `cost(L→L+1) = round(50 × L^1.4)`(占位;幂函数保证后期放缓)。
- 攻速/攻距/移速**不随等级变化**(保持手感锚点);技能 CD 不随等级变化。

### 5.2 星级曲线

- 星级域 `S ∈ [1, 5]`;全属性乘区 `star_mult(S) = 1 + 0.15×(S−1)`(占位)→ [1.00, 1.15, 1.30, 1.45, 1.60]。
- 升星碎片消耗(已拍板(2026-11-06):采用实现值,见 data/economy.json:13 `star_up_cost`、scripts/meta/hero_save.gd:44-48 / :104-116、scripts/autoload/data_db.gd:414-417):原写「[2→3:10, 3→4:20, 4→5:40](3 段,占位,未给 1→2 定价)」→ 实现值「`[10,20,40,80]` **4 段**,`1→2:10, 2→3:20, 3→4:40, 4→5:80`」→ 已拍板。`star_cost(star)` 取 `costs[star-1]`、`star_cap=5`、`star_up()` 有满星前置拦截(`:109`);`data_db.gd:414-417` 校验长度必须 = `ECON_STAR_CAP-1 = 4`,删成 3 段反而挂加载。**1→2 补段后 10/20/40 平移、80 填 4→5,与 DataDB 校验自洽**。

### 5.3 上阵席位(与 RunState.MAX_TEAM 的关系)

- `RunState.MAX_TEAM = 7` **不动**。**上阵席位(已拍板(2026-11-06):采用实现值,见 data/economy.json:26 `item_price.slot_cap`、scripts/meta/hero_save.gd:207-220、scripts/autoload/save_state.gd:19-20)**:原写「闯关席位由 `SaveState.squad.slot_cap` 控制(初始 3,提案解锁至 5,待拍板)、塔保持 7」→ 实现值「**席位统一 3→7,不按模式区分**:`buy_slot_cap` 上限恒 `SaveState.MAX_SLOT_CAP=7 = RunState.MAX_TEAM`,`economy.json:26` 价格表 4 档 `[500,1200,2400,4000]` 覆盖 3→7,战役/塔两入口共用 `squad_edit` 不区分 mode(`scripts/ui/main_city.gd:76-89`、`scripts/ui/squad_edit.gd:167`)」→ 已拍板。`slots[0] 恒 liubei` 不变。battle 侧按 `squad.slots` 实例化单位,formation/HUD 天然支持 ≤6 武将,无需改动。

### 5.4 养成乘区与局内修饰符的叠加模型(关键决策)

- **养成乘区在单位实例化读表时应用**:`hero_unit.gd`/`player_lord.gd` 从 DataDB 读基础值后,先乘 `HeroSave.factors(hero_id)`(= level_mult × star_mult)得到「出场基础值」,再进入现有 RunState 修饰符体系(最终属性 = 出场基础值 × (1 + Σadd%) + Σflat;CD 缩减封顶 40% 不变)。
- 好处:RunState.mods_flat/mods_pct、遗物/强化/事件逻辑**零改动**;存档只在 meta 域生效,战斗内不可变属性。
- 主公刘备同样吃乘区(升星是否开放待拍板,01 §13-7);敌人不吃养成乘区(难度走章节/塔层曲线,§4.4)。

## 8. 战斗核心复用方案:闯关与试炼塔(约束 1/2 落地)

### 8.1 模式上下文注入(RunState 扩展,最小改动)

`RunState` 新增 `mode: StringName`(=`"campaign"` / `"tower"`)与 `context: Dictionary`(闯关=`{stage_id, wave_total}`;塔=`{floor_start}`);`reset()` 签名不变。battle 全程不读 SaveState(战斗层与存档解耦),只读 RunState.mode/context。

### 8.2 波次来源抽象(wave_director 改造点)

现有状态机 `PRELUDE → SPAWNING → BATTLE → INTERMISSION → ENDED` 与分批投放逻辑**原样保留**,只改「波次数据从哪来」:

| 模式 | 波次来源 | 波间队列(after) | 胜负出口 |
|---|---|---|---|
| 塔 | 1~8 层 = DataDB.waves;9+ 层 = tower_wave_gen 生成(逐层生成、过校验后临时注册) | 三选一 → 事件(层号触发)→ 商店(第 4/6 层后)→ 下一层; Boss 层后无波间 | 杀 Boss 才过层;撤退/主公亡 → 结算入库 |
| 闯关 | DataDB.stage_by_id(id).waves 逐波喂入 | 恒空(直接下一波) | 末波结束(或 Boss 关杀 Boss)→ 首通/重复结算入库;主公亡 → 失败(无奖励) |

- `wave_director.gd` 现有 `wave_data = DataDB.wave(wave_idx)` 处抽为 `_load_wave(idx)` 单点:塔模式内改调生成器;闯关改读 campaign 波次。INTERMISSION 的 `_begin_after_queue` 按 mode 分支。**状态机、spawner、HUD、弹窗流程零改动**。
- 闯关波次计时/评星所需的「无武将阵亡」「主公 HP≥50%」在结算时从 RunState.dump() 与战场快照读取(§3.3 评星;实现于 reward_settle)。

### 8.3 塔随机波次生成器(★新增,§4.4 已述契约)

`TowerWaveGen.generate(floor: int, seed: int) -> Dictionary`:纯函数(随机只走传入的 RandomNumberGenerator),输出过 `DataDB._validate_waves()` 同款校验后,由 wave_director 临时持有(不写回 waves.json)。headless 可测(test_tower_gen)。

**已实装(2026-11-06)**:`scripts/meta/tower_wave_gen.gd`(`class_name TowerWaveGen`)+ `scripts/meta/tower_save.gd`(`class_name TowerSave`)。要点:①生成用 `RandomNumberGenerator` 按 seed 新建,**不消耗 RunState.rng**(测试断言 seed/state 前后不变);②失败返回 `{}` + `TowerWaveGen.last_error`,不静默交坏数据;③入口 `DataDB.tower_floor(n, seed)`:1~8 层直出 waves.json,≥9 层走生成器;④`DataDB.tower_is_boss_floor(n)` 为 Boss 层唯一判据;⑤`TowerSave.record_floor()` 只增不减、越界拒绝。战斗层接线:`wave_director._load_wave(idx)` 单点分流(塔/闯关/一段式),状态机与投放逻辑零改动。

### 8.4 奖励结算管道(★新增)

- `RewardSettle.settle(mode, outcome) -> Dictionary`:outcome 含(塔:通过层数/是否阵亡;闯关:stage_id/是否首通/评星/无阵亡/主公 HP 比);按 economy.json 公式(§4.5)算奖励 → 直接调 `SaveState` 入库(军资/碎片/评星/最高层/宝箱)→ 返回奖励清单供结算页展示。

- 塔内三选一临时武将不入 roster(01 §4.2,待拍板):结算时随 RunState 一起丢弃。
- 结算页(result.tscn 改造)展示奖励清单逐项;「回主城」走 SceneRouter.goto_city()。

**已实装(2026-11-06)**:`scripts/meta/reward_settle.gd`(`class_name RewardSettle`)+ `scripts/ui/result.gd` 改造 + `wave_director._settle()` 接线。要点:
